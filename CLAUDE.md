# MaxxHits — Claude Code Project Brief

## What This Is
A multi-company content tracking + **automated posting** app for AimBlue Media, built in PHP + MySQL. Successor to the single-file "Content Board" project, rebuilt as a **multi-page app**: every navigation item is its own PHP page with its own JS file, so editing one page never breaks the others.

## Stack
- **Backend**: PHP 8.x, PDO/MySQL — no frameworks, no Composer, no build step
- **Frontend**: Vanilla JS (one file per page + shared `core.js`), Bootstrap 5.3 CDN, Bootstrap Icons CDN
- **Database**: MySQL (Hostinger shared hosting — no CREATE/DROP DATABASE permission)
- **Auth**: PHP sessions, password_hash/password_verify, CSRF tokens on all mutating requests

## Architecture Decisions
1. **One page = one PHP file + one JS file.** No shared global JS scope across pages; shared helpers live only in `core.js` under the `MH` namespace. Never merge page scripts.
2. **All data via `api/*.php`** returning `{ok:true,data}` / `{ok:false,error}`. Client calls with `MH.api(endpoint, params, method)` — CSRF header added automatically.
3. **Company visibility** is enforced **server-side** with `user_company_filter()` / `can_view_company()` in every endpoint (admin = null filter = sees all).
4. **Secrets** (social login passwords, channel credentials) are AES-256-CBC encrypted with a key derived from `APP_KEY` (generated by config.php, stored in the db config file).
5. **DB config lives above webroot** when writable: `../maxxhits.db.config.php`, falling back to `./db.config.php` (both gitignored, both blocked by .htaccess).
6. **Dual roles**: `users.role` is comma-separated (`content_manager,sales_person`); `cm_person_id`/`sp_person_id` link each role to a `people` record.
7. **Automation**: `channels` hold per-company platform credentials (encrypted JSON). Posts with `publish_mode='auto'` + a channel are picked up by `cron/publish-scheduler.php` when `post_date`/`publish_time` are due. Results land on the post row (`status`, `external_id`, `post_url`, `publish_error`) and in `automation_logs`. The claim UPDATE (`status → publishing`) prevents double-publish from overlapping cron runs.


## Running Locally / Deploying
1. PHP 8.x + MySQL; upload all files to the webroot
2. Visit `config.php` → save DB credentials (writes config + APP_KEY)
3. Import `sql/maxxhits-schema.sql` via phpMyAdmin
4. Visit `setadmin.php` → set the admin password → **delete setadmin.php**
5. Log in at `login.php` as `admin`
6. Automation: add channels on the Automation page, copy the cron URL, add it to Hostinger → Advanced → Cron Jobs (every 5–15 min)

## Conventions
- Escape ALL output: `e()` in PHP, `MH.esc()` in JS
- Every new API endpoint starts with `require_once __DIR__ . '/_init.php';`
- Every new page sets `$PAGE = ['id','title','js']` then includes layout/header.php + footer.php
- Prepared statements only — never interpolate values into SQL
